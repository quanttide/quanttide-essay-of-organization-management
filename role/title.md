# 模块化职位

在通常的组织里，权限长在人身上：授权是一次性的系统操作，与制度上的职位互不对应；人走权失，交接依赖回忆，审计无从下手。量潮把这件事倒了过来——职位同时是制度单位与权限单位，一切授权与回收都通过职位发生。

这一做法有三个要点。

其一，制度与系统同构。任命一个职位，同时完成制度上的授权与系统中的权限开通；解除职位，权限随之回收。系统权限直接绑定在职位上而非任何个人，交接因此不是一项专门工作，而是人事变动的自然结果。

其二，授权可组合、可递归。职权拆成模块之后，既可以整体打包授予，也可以逐项回收、继续下放：职位持有者可以把名下的特定权限再分解成新的职位分配出去。分权不是一次性的制度设计，而是沿着授权链持续发生的进程——一人多职、关键人物的职位清单越长，记录的正是这个进程。

其三，职位清单即权限的单一事实源。想知道一个人能做什么，读他的职位清单；清单以 git 管理，每一次权力变动可追溯、可审计。

两项配套安排支撑这套机制：名分与待遇由特权身份（SVIP）单独承载，不与管理职权混合；组织叙事以主要职位指代人而不称姓名，人事更替不动摇档案与制度的连续性。

本文余下部分先阐述这套机制的制度细节与组织案例，再沿制度实践、系统实现与数据模型三个层面比较它与既有做法的差异，最后讨论它对组织管理系统构建与组织管理职能运营的影响。

## 制度细节

模块的第一维度是权能：职权按决策、执行、仲裁分解，再由章程组合为具体职位。职位不是系统里随手创建的条目，其职权与职责由章程规定，二者互为条件、不可分割——量潮公司代表章程赋予代表五项权能，即信息获取、提案、审议、表决与程序异议，同时规定任何机构不得架空代表职权，代表亦不得以放弃职权推卸职责。章程与档案在此分工：章程定义槽位，档案记录在任者，人事更替不动章程、只动档案。制度档案与章程称职务，本文统一称职位。

量潮把通常纠缠在一起的三个东西拆成三本独立登记的册子：职级承载资历与待遇，按序列与等级挂钩薪酬；特权身份（SVIP）承载名分与礼遇；职位承载职权。三本册子独立变动——晋升职级不必伴随授权，授予职权不改变待遇，保留名分不保留权力。组织里常见的「提待遇就要给头衔、给头衔就顺带放权」的捆绑，在制度上被切断，这是第一项配套安排。

职权可以继续分解。职位持有者把名下的特定权限拆成新的职位分配下去，授权链随之延长一级。授权的粒度决定治理的形态：授权越细，组织自治的覆盖面越大；留在手中的职权越多，集中行使的空间越大。分权不是一张静态的结构图，而是可以持续推进的进程。

职权的记录在两层同时成立：制度层，代表的每一次表决记入履职档案；系统层，权限的开通与回收随任命与解除自动发生。两层记录指向同一个单位——职位，职位清单由此构成职权的唯一权威源。档案同时承载组织叙事：以主要职位指代人而不称姓名，人事更替不动摇档案与制度的连续性，这是第二项配套安排。

## 组织案例

量潮创新联盟设三大机构：理事会定方向，代表大会审议，秘书处执行。职位按机构归属设置——理事、代表、秘书长、副秘书长、秘书。值得注意的现象是，秘书处的每一职都由联盟代表兼任：同一个人在执行线与决策线上各占一个职位，两个职位分属不同机构、各自独立授予与回收。一人多职在这里不是职权混淆，而是机构间授权在个人身上的合成；兼任随时可以拆开而不动摇任何一机构，这正是模块化的证据。

理事会内设理事会秘书，由理事兼任。参与决策的职位与保障决策运转的职位在制度上分立，是否由同一人担任则视人力而定：分立是设计，兼任是安排。让决策成员自己承担决策的运转成本，而不是把会务与记录外包给旁观者，是这个设计的意图。

授权链有现成的实例：联盟账户的超级管理员权限绑定在秘书处与理事会的职位上，由任职者持有；任职者再把所辖范围的特定权限分解为新的职位分配下去。每一次分解都在档案中留痕，链条上的每一环都可以单独回收。

## 与既有做法的比较

差异沿三个层面观察：制度实践、系统实现与底层数据模型。

与岗位制比较。一般企业的岗位说明书记载职责与汇报关系，是人力资源工具；系统权限由管理员逐人授予，与人事制度互不相连。模块化职位的清单只记载职权，并且直接映射为系统权限——人事操作与权限操作是同一个操作。岗位制回答谁负责什么，职位清单回答谁被授予了什么。

与历史官制比较。以官职分解权力在中国官制中高度发达，名分、实职与虚衔的区分古已有之；差异不在分解，而在可逆性。历史上收回一套权力往往需要政治事件，模块化把授予与回收都变成常规操作——分解的价值从名分的确立转移到权力的流通。官职样本的详细分析见教程《以钱弘俶为例解读组织中的“职位”》，此处不赘。

与访问控制中的角色模型比较。信息系统领域早有把权限绑定到角色的做法，与模块化职位形似，差别有二。其一，角色只覆盖系统层，职位同时承载制度职权：表决、提案、仲裁无法写成访问控制条目，却是职位的题中之义。其二，角色的增删由系统管理员决定，职位的设置受章程约束、变动走组织程序。可以把职位理解为横跨制度层与系统层的统一绑定单位，角色是它在系统层的特例。

与现行系统的临时授权比较。多数系统也有授权，但以「代理」「临时授权」的例外形式存在——为一次差旅开一轮权限，回来再关，授权是系统里的补丁。模块化职位把递归授权变成常规机制：授权链上的每一环都是正式职位，有档案记录、有独立生命周期，临时性不再是授权的常态。

与主流套件的组织模型比较。协同办公与人事套件同样维护组织架构，但其模型以员工为主实体：职位是员工档案上的一个字段，汇报线是员工之间的连线，权限是挂在账号上的配置，职位清单散落在各系统后台、随配置者变动。模块化职位把清单的所有权交还组织：归组织所有、走组织程序变更。这一数据模型的差异，是下一节系统设计的起点。

## 组织管理系统的构建

系统以职位为主实体，核心是三类事实：职位、任职、授权链。每条职位记录包含章程依据、职权清单、授予来源与现任者；任职是人与职位之间带时间的记录，任命与解除各自留痕；授权链记录职位之间的授予关系——哪个上游职位把哪部分职权分解给了哪个下游职位。组织架构不再是「人加汇报线」，而是这三类事实的总和。

职位清单以文本数据入仓，以 git 管理，写权限受控，变更走审批，每次调整有版本历史。由于系统的权限状态由清单推导，这份版本历史自动成为权限变更日志——审计不必另建一套日志，回读清单的历史就是回读权力的历史。

各业务系统的权限不再逐人配置，而是由清单驱动：任命即开通，解除即回收，或由管理员按清单执行，或由同步工具自动完成。系统定期比对实际权限与清单推导出的应然权限，不一致即告警。漂移检测让「权限长在人身上」无处藏身，也让档案纪律从要求变成校验。

授权链一旦可查询，三类以往依赖记忆的事务都变成查询。回收一个上游职位，系统列出受影响的下游职位，提示级联处理；人员离开，系统按其职位清单列出全部待交接事项与空缺；新人到来，按其将就任的职位批量开通入职包与权限。交接从专门工作降格为一次查询。

建设路径宜数据先行：先以手工维护的文本清单跑通唯一权威源，让组织把它当作每次调动的必写处；再上比对与告警，让档案纪律有机器兜底；然后做自动同步，让任命即开通、解除即回收不依赖人的执行；最后开放授权链的级联管理，把递归授权变成系统的一等能力。应用层始终同构于数据层，工具是习惯的载体。

## 组织管理职能的运营

组织管理职能的工时结构随之改变。传统运营的大部分人力耗在人事操作上：开权限、改配置、催交接、对口径，操作散落在多个系统与群聊里。模块化职位把这些操作折叠进任命与解除之后，职能剩下的核心工作是职位体系本身——设哪些职位，职权如何分解，授权链往哪里延伸。

日常运营收敛为一组明确的动作：任命与解除是唯一的授权入口，人事之外不存在特殊授权；清单随任命实时更新，实时性是机制的生命线；定期比对实际权限与清单，巡查授权链上长期未分解的职权、长期空缺的职位与可以拆开的兼任。空缺不是事故而是信号——槽位先于人头，空槽位公开可见，由谁补位、何时补位进入组织议程。

职级与职位的分离改变了人才职能的抓手。定级定薪沿职级序列进行，不牵动职权；培养路径表现为职位序列——从部门秘书到秘书长，每一站是一次任命，培养的完成以授权的交割为标志。人才发展与授权在档案里互相可见，又互不牵连。

职权争议的运营成本随之下降。谁能做什么，不再依赖回忆与权威裁定，查档案即得；组织管理职能从裁判者退回书记员，把裁量的空间留给章程与档案。

## 结论

模块化职位的要点可以归结为一句话：让职权像模块一样流通，以职位为授予、回收、审计与继续分解的单位。制度、系统与档案因为共享同一个单位而互相咬合，授权与回收折叠进人事操作，审计折叠进档案。

这套机制有代价。职位清单越长，可读性越差；形式化的维护依赖档案纪律，制度若不随任命实时更新，权限与职位的对应立即失真；职位设计不当还会退化成头衔堆砌。模块化分权的有效性取决于分解的纪律，而不是分解的形式。

对组织管理系统，它意味着以职位为主实体、以清单为权限源的重构；对组织管理职能，它意味着从人事操作转向职位体系的设计与维护。两条路服务于同一件事：让分权作为常规进程持续发生。职位清单的长度，就是它的刻度。
